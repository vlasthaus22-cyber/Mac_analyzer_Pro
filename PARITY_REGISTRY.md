# Реестр полного переноса PyQt -> Web

Правило готовности: строка может быть отмечена только после наличия web-экрана
или REST API, теста и сохранения данных в SQLite там, где это делает исходник.

## Ядро данных

- [x] APICache и MACVendorAPI: кэш, выбор сервиса, rate-limit, тест API.
- [x] VendorDatabase и VendorDetector: OUI, MAC5, confidence, source,
  inference from similar devices, custom mappings. Автоопределение использует
  индексированный приоритет OUI/MAC-префиксов 5→4→3 байта, затем текст,
  похожие устройства и историю; модель определяется по точному/совместимому
  MAC5 и истории с сохранением источника и уверенности. Backend-код этого
  блока изолирован в `backend/services/detection`.
- [x] Внешний справочник PyQt `oui.txt`: корневой TXT/CSV безопасно переносится в `data/reference`,
  IEEE/corporate Assignment/OUI импортируется бинарно без Base64, синхронизируется с SQLite и применяется
  автоматически по префиксам 3/4/5 байт; пользовательские правила не перезаписываются.
- [x] MACHistoryDatabase: все операции поиска, фильтра, удаления и статистики.
- [x] VendorModelHistory и HistoryEnricher: загрузки, обучение, статистика.
- [x] IPToAddressMapper: импорт, автоопределение, ручные правила и экспорт.
- [x] AutoColumnDetector, AIColumnDetector и ColumnConflictDialog: оценки уверенности, альтернативы, примеры данных, ручное подтверждение/отмена, автовыбор и обязательная колонка MAC.
- [x] StatisticsDatabase: snapshots, trends, history, performance metrics.
- [x] SettingsManager, AppLogger, AutoSaveManager, SignalHandler.
- [x] Структурированное хранение: основная SQLite-база, legacy-базы истории,
  резервные копии, импорт/экспорт, runtime-файлы, логи и настройки разнесены по
  отдельным папкам; старые файлы автоматически мигрируют без перезаписи.
- [x] Структура сопровождения проекта: документированная карта каталогов,
  отдельные PowerShell-команды запуска/остановки backend и полного тестирования,
  изолированные каталоги `tests` и `tools`, контекст `.agents` и корректно
  инициализированный локальный Git-репозиторий.
- [x] Аналитический backend структурирован в `backend/services/analytics`:
  графики, dashboard, отчёты, качество данных, аналитика устройства, топология
  и кластеризация используют пакетные импорты; корневые файлы оставлены только
  как совместимые адаптеры для старых интеграций Python-версии.
- [x] Интеграционные сервисы структурированы в `backend/services/integrations`:
  внешнее vendor API, Email/Telegram/Slack и очередь планировщика подключены
  пакетными импортами с сохранением прежнего Python API через адаптеры.
- [x] Сравнение и экспорт структурированы в `backend/services/comparison` и
  `backend/services/exporting`: единый менеджер форматов использует внутренние
  text/PDF-модули и workspace XLSX, а старые импорты сохранены адаптерами.
- [x] Системные сервисы структурированы в `backend/services/system`: единая
  карта хранилища, безопасная миграция legacy SQLite и машинный parity-аудит
  используются backend и tools через пакетные импорты.
- [x] Браузерный импорт структурирован в `frontend/file-readers.js`: чтение
  CSV/TSV/JSON, определение кодировки и чистый XLSX/ZIP parser отделены от
  контроллера `app.js` и работают как через HTTP, так и через `file://`.
  Автономный XLSX распаковывает только необходимые части книги, читает строки
  листа потоково без полного XML DOM и использует `frontend/memory-guard.js`.
- [x] Пакетное ускорение обогащения: правила, история vendor/model и IP-адреса
  загружаются из SQLite один раз на анализ; префиксы индексируются в памяти,
  история сохраняется через `executemany`, а прогресс ограничен примерно 100
  обновлениями независимо от числа строк. Браузерный режим использует те же
  предварительно скомпилированные индексы 3/4/5 байт.
- [x] ColumnManager: видимость, порядок, пользовательские столбцы, ручная ширина,
  оптимизация, сброс и сохранение ширины в SQLite.
- [x] ExportManager: Excel, CSV, TXT, HTML, PDF, JSON, YAML. CSV, TXT,
  HTML, JSON, YAML, SpreadsheetML и server-side PDF перенесены. Настоящий
  XLSX формируется как автономно в браузере, так и через backend. Браузерный
  экспорт потоково читает полный финальный snapshot из IndexedDB, создаёт
  валидный ZIP/XLSX без копии всего массива устройств и сохраняет все строки,
  а не только видимую страницу. Дополнительная кнопка формирует одну
  многолистовую книгу со сводкой, всеми устройствами, аналитикой, выгрузками,
  полной доступной хронологией каждого MAC, изменениями, ошибками, исходными
  файлами, справочниками и настройками; большие разделы истории автоматически
  разделяются по листам в пределах стандарта Excel. Схема полного отчёта и
  разбиение истории выделены из UI-контроллера в тестируемый модуль
  `frontend/full-xlsx-report.js`, а низкоуровневая ZIP/XLSX-запись остаётся в
  `frontend/xlsx-exporter.js`. Полная книга содержит оформленные заголовки,
  фиксированную верхнюю строку, фильтры, ширины колонок, цветовые вкладки и
  расширенную сводку с содержанием всех листов.

## Основные рабочие экраны

## Сервисы и системные функции

- [x] Внешнее API-обогащение с выбором устройств и настройкой сервисов:
  отдельный APISettingsDialog, macvendors/maclookup/mac2vendor, тестовый MAC-запрос,
  SQLite-сохранение, кэш/rate-limit и локальная OUI-проверка без backend.
- [x] Уведомления: Email, Telegram, Slack, тесты и события анализа.
- [x] Планировщик реальных задач и очереди файлов.
- [x] AI-анализ качества данных.
- [x] Быстрое обогащение больших XLSX: серверный кэш импортов с токенами,
  автоматическое восстановление после перезапуска backend из `data/imports/workspace-cache`, компактные payload
  списка файлов/сопоставления, бинарная загрузка без Base64-копии, пакетная IndexedDB-запись и компактный autosave.
- [x] Защита больших анализов от Out of Memory: результаты выводятся страницами по 25-1000 строк,
  SQLite-снимок сохраняется в том же запросе обогащения, а компактный HTTP-ответ содержит только первую страницу,
  итоговые счётчики и `snapshotId`. Фильтры, аналитика, dashboard и экспорт получают полный набор по ссылке из SQLite;
  bootstrap хранит только метаданные снимков, открытие истории также выполняется постранично. Модуль
  `frontend/state-persistence.js` не клонирует в IndexedDB строки XLSX с серверным `fileToken` и данные SQLite-снимка,
  сохраняя полные строки только для автономного HTML-режима без backend. Backend-импорт возвращает только 25-500
  строк превью (по умолчанию 100), а полный набор остаётся в ограниченном файловом кэше и используется по токену.
  Автономное обогащение выполняется порциями без полных `slice/filter/sort`-копий; превышение безопасного числа строк,
  ячеек, shared strings или размера XML останавливается управляемой ошибкой до аварийного завершения вкладки.
  Повторные автономные обогащения хранят полные снимки отдельно в `frontend/browser-snapshot-store.js`, а в рабочем
  состоянии оставляют метаданные и превью до 500 строк; предыдущий большой результат освобождается после построения
  компактного индекса изменений. Дисковый лимит IndexedDB сохраняет последовательность больших финальных снимков,
  а dashboard сравнивает пары без загрузки полных массивов в память. Переносимый `mac_analyzer_standalone.html` также ограничивает снимки, persisted state
  и DOM-таблицу, поэтому второй и последующие прогоны не умножают полные копии массива устройств. Interval/manual/
  beforeunload autosave всегда сохраняет компактное состояние; автономная очередь не клонирует строки и освобождает
  результаты завершённых задач. Внешнее API-обогащение большого серверного результата принимает `snapshotId`, сохраняет
  новый полный SQLite-снимок и возвращает только ограниченную страницу. Постоянный тест
  `tests/test_repeated_enrichment_memory.py` выполняет четыре последовательных двухфайловых обогащения и проверяет,
  что живые промежуточные аллокации между циклами не накапливаются.
  Карточка MAC использует `frontend/mac-chronology.js` и точечный
  `BrowserSnapshots.findDevice`: хронология по клику загружается из всех
  сохранённых IndexedDB-снимков, даже если MAC отсутствует в предпросмотре.
  Browser и backend-события объединяются без полной загрузки снимков в память.
  Перенос между ПК и браузерами использует общую файловую базу
  `database/mac-analyzer-data.madb`: Chrome/Edge подключают каталог на чтение и
  запись, а остальные браузеры импортируют выбранную папку через FileList.
  Восстановление потоково записывает снимки в IndexedDB и удерживает только 250
  строк предпросмотра; очищенный IndexedDB больше не блокируется устаревшей
  меткой синхронизации из localStorage.
  Создание снимка, IP-маппинг, уведомления анализа и очередь планировщика используют компактные ссылки
  `snapshotId`/`fileToken`; применение IP-маппинга сохраняет полный результат в SQLite и возвращает только страницу.
  Локальный текстовый экспорт проверяет отдельные лимиты строк и ячеек до построения таблицы в памяти.
  Автономный XLSX экспортируется отдельным `frontend/xlsx-exporter.js`: XML листа строится порциями,
  ZIP-каталог и CRC формируются в браузере, а Blob URL остаётся действительным до начала скачивания.
  Автономное обогащение проверяет суммарное число строк и ячеек основного и всех дополнительных файлов до
  построения MAC-индекса. Переносимый standalone HTML также ограничивает сжатый XLSX, каждую ZIP-часть,
  общий распакованный XML и shared strings до выделения опасного объёма памяти.
  Весь встроенный JavaScript standalone HTML компилируется отдельным Node-тестом при каждом полном прогоне.
  Перед автономным обогащением дополнительно проверяются суммарный объём текста и доступный JS heap; полный локальный
  результат записывается один раз в отдельный snapshot-store, а workspace хранит только ссылку. Однофайловый HTML
  освобождает предыдущий результат до построения следующего и очищает временный MAC-индекс после завершения.
  Ранняя проверка импорта ограничивает сжатый размер одного файла, суммарный размер основной и дополнительных книг,
  число ZIP-разделов и общий распакованный объём до чтения XML. Backend-анализ одного файла использует бинарную
  загрузку и `fileToken` вместо Base64, сохраняет полный SQLite-снимок и возвращает только первую страницу.
