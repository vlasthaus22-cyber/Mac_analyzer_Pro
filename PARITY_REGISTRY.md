  устаревшая вторичная ссылка больше не создаёт ложный конфликт и лишние изменения.

## Точные изменения, модели и охват помещения (v1.0.61)

- [x] Конфликты идентификации/источников хранятся как диагностика и не
  увеличивают фактические счётчики изменений между Final.

## Восстановление входных файлов и быстрые вкладки (v1.0.59)

- [x] Оригиналы основного, SmartRoom и DDIO-файлов сохраняются в IndexedDB при
  любом способе импорта; локальная папка используется как дополнительный

- [x] Повторное открытие неизменённой вкладки использует сигнатурный кеш уже
  созданного представления; потоковое автономное обогащение пишет более
  крупными безопасными пакетами и реже блокирует главный поток.

## Безопасное IndexedDB и полные графики Final (v1.0.58)

- [x] Производный DDIO-индекс и dashboard-кеш больше не дублируются в одной
  записи рабочего состояния; потоковые записи проходят ограничение размеров и
  очистку несериализуемых значений до `IDBObjectStore.put`.
- [x] Поиск совпадений по multi-entry индексу ограничен двумя результатами,
  массивы конфликтов/альтернатив ограничены, а DataClone/OOM получает отдельную
  диагностику без повреждения последнего успешного Final.
- [x] Каждая комната получает состояние для каждого Final, включая отсутствие;
  каскад ТБ → Город → Площадка → Этаж → Помещение нормализует регистр и пробелы,
  единственная найденная комната выбирается автоматически.
- [x] Кнопка проверки всех устройств комнаты сравнивает два последних Final и
  сохраняет известные непустые значения через временное отсутствие комнаты.
- [x] Первый Final исключён из добавлений/отсутствий; добавления рисуются выше
  нуля, «Отсутствовало» — ниже нуля. Общее число устройств показывает всю
  последовательность Final от первого до последнего.

- [x] IP из DDIO подставляется только в отсутствующее поле устройства,

- [x] Автономная MADB и backend SQLite описаны отдельной инструкцией без

## Диагностика, графики и полные хронологии (v1.0.53)

- [x] Пустые строки не считаются ошибочными устройствами, а некорректный MAC
  или отсутствие сильного идентификатора сопровождаются причиной, исходным
  значением, номером строки и рекомендацией по исправлению.
- [x] Графики Chart.js получают числовые массивы в совместимом формате и
  автоматически строятся после восстановления постоянной базы даже при прямом
  открытии вкладки «Аналитика».
- [x] Хронология помещения показывает добавления, удаления, изменения и
  перемещения между IP/портами коммутатора, не размножает дубли источника и
  использует Device ID, serial или hostname при отсутствии MAC.
- [x] Хронология MAC сохраняет всю загруженную цепочку, объединяет одно
  появление из browser/backend, не создаёт ложное изменение при пустом новом
  поле и показывает корректные UTC-даты от первого появления до текущего.
- [x] Русские и технические имена полей/типов изменений приводятся к единой
  схеме; критическими считаются только подтверждённые изменения MAC, IP
  устройства или IP коммутатора с непустыми старым и новым значениями.

- [x] Все модули открывают общую IndexedDB версии 11; fallback больше не

  альтернативы сохраняются, конфликтные значения автоматически не применяются.

## Стратегия количества строк обогащения (v1.0.50)

- [x] `NO_EXPANSION` ограничивает текущий Final уникальными устройствами файла №1.
- [x] `ALLOW_EXPANSION` разрешает добавлять только достоверно идентифицированные устройства SmartRoom.
- [x] DDIO, Previous Final, история, конфликты и Possible IPs не создают строки Final.
- [x] При ошибке браузерного или SQLite-сохранения предыдущий успешный Final остаётся активным.

Правило готовности: строка может быть отмечена только после наличия web-экрана
или REST API, теста и сохранения данных в SQLite там, где это делает исходник.

## Ядро данных

- [x] Устройства, присутствующие только во втором файле, сохраняются в Final только в явном режиме `ALLOW_EXPANSION`; в `NO_EXPANSION` они остаются диагностическими несопоставленными записями. DDIO заполняет отсутствующий IP устройства с явным источником, но не создаёт Final-строки. Единый identity-сервис нормализует MAC, hostname, серийный номер и Device ID, отвергает неоднозначные слабые совпадения и переносит только непротиворечивые сведения последнего финального состояния.
- [x] Отдельная страница «Изменения IP» удалена. Смена IP коммутатора сравнивается с предыдущим финальным состоянием и отображается как критическое изменение вместе с отдельным IP устройства и вариантами из DDIO.
- [x] SQLite inventory/history добавочно хранит hostname, серийный номер, Device ID/name, источники полей и конфликты; непустые известные значения защищены от затирания, одинаковое повторное наблюдение не дублируется, пользовательский режим открывается на поиске по полному inventory.

- [x] Мониторинг Smartroom использует Smartroom ID как стабильный ключ,
  показывает исчезнувшие устройства, историю смен IP с DDIO `Possible_IPs`,
  полную хронологию помещения и MAC-переходов. Тяжёлые агрегаты выполняются
  порционно в Web Worker, вкладки монтируются лениво, большие таблицы имеют
  стабильное виртуальное окно 20 строк, а Chart.js встроен в автономный HTML,
  валидирует входные ряды и показывает No Data/ошибку вместо пустого canvas.
  Даты хронологий нормализуются в UTC с динамическими интервалами, а помещения
  фильтруются по явному полю города без ошибочного использования улицы.
- [x] Текущая финальная выгрузка имеет приоритет: старые файлы обогащения
  заполняют только пустые поля и не перезаписывают модель, производителя, адрес,
  помещение, IP/порт коммутатора и источник основного файла.
- [x] DDIO-предупреждение о смене IP коммутатора создаётся только после строгого
  сравнения с предыдущим значением из IndexedDB/SQLite; вторичный файл не имитирует историю,
  а возможные адреса проходят проверку IPv4/IPv6 до подсветки.

- [x] APICache и MACVendorAPI: кэш, выбор сервиса, rate-limit, тест API.
- [x] VendorDatabase и VendorDetector: OUI, MAC5, confidence, source,
  inference from similar devices, custom mappings. Автоопределение использует
  индексированный приоритет OUI/MAC-префиксов 5→4→3 байта, затем текст,

- [x] Внешний справочник PyQt `oui.txt`: корневой TXT/CSV безопасно переносится в `data/reference`,
  IEEE/corporate Assignment/OUI импортируется бинарно без Base64, синхронизируется с SQLite и применяется

  Валидный UTF-8 без BOM выбирается до legacy-кодировок, поэтому кириллица CSV
  не искажается эвристикой Windows-1251; сценарий закреплён регрессионным тестом.
  Автономный XLSX распаковывает только необходимые части книги, читает строки
  листа потоково без полного XML DOM и использует `frontend/memory-guard.js`.
- [x] Третья выгрузка DDIO изолирована в `frontend/ddio-overlay.js` и
  `backend/services/workspace/ddio_overlay_service.py`: пары MAC/IP резервации и аренды
  сопоставляются независимо, селекторы доступны для колонок после H и показывают буквы
  Excel, а новый IP показывается подчёркнутой подсказкой только при фактической смене IP

  поля устройств, снимки и экспорт; в истории изменений сохраняется только служебная

- [x] Пакетное ускорение обогащения: правила, история vendor/model и IP-адреса

  обновлениями независимо от числа строк. Браузерный режим использует те же

- [x] Повторное обогащение восстанавливает по точному MAC последнее непустое
  значение каждого поля отдельно, поэтому поздняя неполная выгрузка не скрывает

  подключается к SQLite рядом с программой; режим `file:` остаётся полностью
  автономным. Версии общей IndexedDB синхронизированы, повторный рендер тяжёлых
  вкладок аналитики и истории кэшируется, контраст статусов проверяется для обеих тем.
  Интерактивные иконки аналитики и вложенные подписи выбранных карточек всегда
  используют контрастный цвет активной темы.
- [x] Сортировка таблиц доступна кликом и клавишами Enter/Space по заголовку:
  основная таблица сортирует полный backend-снимок или ограниченное по памяти
  потоковое окно IndexedDB, остальные обычные таблицы сортируются в DOM без
  повторного запроса. Поиск использует debounce, отменяет устаревшие запросы,
  страницы результата и хронология устройства имеют ограниченный короткий кэш,
  а тяжёлые вкладки начинают расчёт после немедленного показа нового экрана.
- Smartroom Monitor v2: IndexedDB v8 добавляет безопасные индексы
  `by_smartroom`, `by_mac`, `by_switch`, `by_timestamp` и переносимое хранилище
  `KnownModels`; пустой Smartroom ID не попадает в Equipment. DDIO индексирует
  возможные IP по MAC и Device ID, история показывает раскрываемую ❗-подсказку,
  а полная MAC-хронология отображается горизонтальной интерактивной лентой.
