# MAC Analyzer Pro Web

## Запуск

1. Используйте Python 3.10 или новее.
2. В папке проекта выполните:

   python server.py

3. Откройте http://127.0.0.1:8080

Готовые команды находятся в `scripts/`: `start_server.ps1` запускает backend
в обычном или фоновом режиме, `stop_server.ps1` останавливает фоновый процесс,
а `run_tests.ps1` запускает все проверки без установки pytest. Полная карта
каталогов приведена в `PROJECT_STRUCTURE.md`.

## Перенос на другой компьютер

### Один автономный HTML без EXE и CMD

Для рабочих мест, где запрещён запуск EXE, CMD, PowerShell и Python, создаётся
однофайловая сборка:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_html_portable.ps1
```

Готовый файл `portable/html/MAC-Analyzer-Pro.html` открывается двойным щелчком и
не запускает backend и не обращается к localhost. XLSX/CSV/JSON импорт,
обогащение, поиск, история, аналитика, темы и пользовательский/инженерный режим
работают внутри браузера. Быстрое автосохранение выполняется в IndexedDB.
Кнопка `Скачать всё XLSX` на странице «Анализ» создаёт одну многолистовую книгу:
сводка, устройства, аналитика, выгрузки, хронология каждого MAC, изменения,
ошибки, исходные файлы, справочники и настройки. Листы имеют фиксированные
заголовки, фильтры, настроенные ширины колонок и цветовую навигацию.
Двойной клик по MAC открывает вертикальную хронологию, объединяющую появления
из IndexedDB/SQLite и изменения между выгрузками.

Нажмите `Локальная база` и один раз выберите папку. Программа создаст в ней
`database`, `imports`, `exports`, `settings`, `logs` и `backups`. Рабочее состояние
читается из `database/mac-analyzer-data.madb`, изменения записываются туда автоматически,
а исходные XLSX/CSV сохраняются отдельно в `imports`. MADB записывается и читается последовательно небольшими
порциями, поэтому повторные обогащения не создают ещё одну полную JSON-копию
результата в памяти. Из-за правил безопасности браузера пользователь один раз
выбирает папку вручную на каждом новом компьютере и в каждом новом браузере.
Chrome/Edge подключают её на чтение и запись. Если прямой доступ к папке не
поддерживается, кнопка `Прочитать папку в браузере` находит
`database/mac-analyzer-data.madb` во всём выбранном каталоге, потоково
восстанавливает снимки в IndexedDB и оставляет в памяти только страницу
предпросмотра. В таком режиме изменения переносятся через сохранение отдельного
MADB. SQLite из `data/databases` автономный HTML напрямую читать не может.

При следующем открытии страница сразу показывает последний снимок из локального
кэша, затем проверяет только заголовок MADB. Полное чтение файла выполняется лишь
когда база в папке новее кэша. Если IndexedDB был очищен, наличие только метки
времени больше не мешает восстановлению из MADB. Неизменённая база больше не
переписывается каждую минуту, а повторный импорт одного исходного файла обновляет
его архивную копию.

Исходные `index.html`, `app.js` и модули остаются раздельными для разработки.
Пользовательская HTML-сборка содержит их встроенными и передаётся одним файлом.

Полный архив для приватного Release создаётся командой
`scripts/build_complete_release.ps1`. Он содержит автономный HTML, исходный
PyQt-файл, frontend/backend, Python API, сервисы, тесты, инструменты и локальные
`data`, `config`, `logs`. Старые вложенные релизы, временные build/runtime-файлы,
EXE, DLL и CMD исключаются; состав и SHA-256 каждого файла записываются в
`FILE_MANIFEST.sha256`.

### Вариант с Python/SQLite backend

Для передачи пользователю или инженеру создайте один универсальный пакет на
компьютере разработчика командой:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_portable.ps1
```

Команда создаёт только один вариант: `portable/dist/MACAnalyzerBackend`.
Передавайте всю эту папку целиком или один ZIP-архив с её содержимым. Пользователь
всегда запускает только `START_MAC_ANALYZER.cmd`; выбирать и скачивать отдельную
сборку для пользовательского или инженерного режима не требуется.
Резервный `mac_analyzer_standalone.html` остаётся только в исходном репозитории и
не включается в пользовательский пакет: рабочим интерфейсом является `index.html`.

Универсальный пакет хранит пользовательские данные внутри `data/`. Все браузеры,
открытые через один запущенный backend, получают общий workspace, результаты,
историю и настройки из локальной SQLite. Полные строки XLSX не включаются в
bootstrap-ответ: браузер получает только токены файлов, метаданные и страницы
результатов.

Готовая папка находится в `portable/dist/MACAnalyzerBackend`. Переносить нужно
всю эту папку целиком. На другом Windows-компьютере запустите
`START_MAC_ANALYZER.cmd`. Лаунчер сначала использует доступный пользовательский
Python и `server.py`. Если Python отсутствует, он автоматически запускает встроенный
резервный backend. Резервный backend собран с Windows-манифестом `asInvoker`, не
запрашивает повышение прав и не требует установки. `STOP_MAC_ANALYZER.cmd` корректно завершает
процесс. SQLite, история, настройки, кэш, экспорт и журналы создаются внутри
перенесённой папки в отдельных `data/`, `config/` и `logs/`; пользовательские
рабочие базы в сборку не копируются.

При первом запуске через Python лаунчер при необходимости создаёт `.venv-portable`
внутри папки программы. Эта операция выполняется в профиле обычного пользователя и
не требует административных прав. Если корпоративная политика полностью запрещает
PowerShell, Python и неизвестные исполняемые файлы, её должен разрешить системный
администратор: приложение не пытается обходить политики безопасности Windows.

## Структура хранения

Рабочие данные отделены от исходного кода:

```text
data/
  databases/  основная SQLite-база и WAL/SHM
  legacy/     базы истории старой PyQt-версии
  backups/    резервные копии состояния
  exports/    серверные экспортные файлы
  imports/    временные импортируемые файлы
  runtime/    временные данные процессов
logs/         журналы Python и backend
config/       локальные настройки
```

При первом запуске известные файлы из корня проекта переносятся автоматически без
перезаписи уже существующих файлов. Основная база создаётся как
`data/databases/mac_analyzer_web.db`. Путь можно изменить переменными
`MAC_ANALYZER_DATA_DIR` и `MAC_ANALYZER_DATABASE_PATH`.

## Автоопределение и производительность

Backend один раз загружает правила OUI/MAC5, историю vendor/model и IP-правила
для всего анализируемого набора. Производитель определяется по самому длинному
префиксу 5/4/3 байта, затем по тексту и похожим устройствам. Модель определяется
по точному или совместимому MAC5-префиксу и истории. Пакетное сохранение истории
и ограничение обновлений прогресса устраняют отдельные SQLite-запросы для каждой
строки. Автономный JavaScript использует предварительно скомпилированные индексы.

После импорта backend возвращает временный `fileToken`: повторное обогащение
передаёт только токен, роль файла и выбранное сопоставление колонок, а не все
строки XLSX. Кэш ограничен временем, количеством файлов и строк; после
перезапуска backend frontend автоматически один раз повторяет запрос с полными
строками и получает новые токены. Список файлов и сетка сопоставления также
используют компактные payload. Частые сохранения браузера объединяются в одну
запись IndexedDB, а SQLite-autosave хранит ссылку на уже созданный снимок вместо
дублирования всех устройств и строк файлов.

Локальные снимки IndexedDB записываются отдельными блоками по 1 000 строк.
При сохранении переносимой MADB прошлые снимки передаются блоками напрямую из
IndexedDB в файл, поэтому второй и последующие результаты не создают полную
промежуточную копию истории в памяти браузера.

Настройки серверного кэша: `MAC_ANALYZER_WORKSPACE_CACHE_TTL` (секунды),
`MAC_ANALYZER_WORKSPACE_CACHE_FILES` и `MAC_ANALYZER_WORKSPACE_CACHE_ROWS`.
Текущую статистику возвращает `GET /api/workspace/cache`. Замер JSON-payload:

```powershell
.venv\Scripts\python.exe -m tools.benchmark_workspace_payload
```

## Защита от Out of Memory

Frontend проверяет число строк, ячеек, суммарный объём текста XLSX и доступный
JS heap до создания MAC-индекса. Если безопасного запаса недостаточно, операция
останавливается управляемым сообщением `BROWSER_MEMORY_LIMIT`, не начиная
опасное выделение памяти. В автономном режиме полный результат хранится один
раз в отдельном IndexedDB snapshot-store; workspace и localStorage содержат
только ссылку, метаданные и ограниченное превью. Повторный анализ standalone
HTML освобождает предыдущий результат и временный MAC-индекс перед сохранением.

Основной файл и файлы обогащения не удерживаются в памяти одновременно: workspace сохраняет
только заголовок и 100 строк предпросмотра, а автономный анализ повторно читает исходные Blob
последовательно, освобождая строки очередного XLSX перед переходом к следующему. Полные
браузерные снимки также удаляются до записи нового снимка при превышении бюджета 300 000 строк.

До чтения автономного файла также проверяются его сжатый размер, суммарный размер
основного и файлов обогащения, доступный JS heap, число ZIP-разделов и общий
распакованный объём XLSX. Анализ одного файла через backend передаёт XLSX бинарно,
повторно использует `fileToken` и получает только ограниченную страницу результата;
Base64- и полноразмерная JSON-копии в памяти браузера не создаются.

Для файлов, превышающих автономные лимиты, используйте переносимый backend:
он хранит полный набор и историю в SQLite, а браузеру возвращает только страницу
результатов размером 25–1000 строк.

External OUI lookup is disabled by default. To enable it, set
MAC_ANALYZER_ENABLE_EXTERNAL_LOOKUP=true before starting the server.

SMTP credentials are accepted only for the test request and are never written
to the SQLite database.

## Проверка parity

Запустите полный набор проверок без зависимости от pytest:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run_tests.ps1
```

Отдельная smoke-проверка REST API и UI-контролов:

```powershell
.venv\Scripts\python.exe -m tests.test_web_api_ui_smoke
```

Обновить машинный отчёт переноса:

```powershell
.venv\Scripts\python.exe -m tools.generate_parity_status
```

### Повторное автономное обогащение без backend

При открытии единственного HTML полный результат сохраняется в локальной IndexedDB-базе
`mac-analyzer-browser-storage-v1` блоками по 1 000 строк. Рабочее состояние содержит только
текущую страницу, а временная таблица `enrichmentRows` выполняет само слияние файлов пакетами без полного `Map` в памяти.
метаданные, 100 строк предпросмотра файла и текущую страницу результата. Повторное открытие,
поиск и переход по страницам сканируют блоки базы последовательно и не восстанавливают весь
снимок в `state.devices`. Для набора выше автономного лимита операция останавливается до
выделения памяти с сообщением `BROWSER_MEMORY_LIMIT`; запуск Python или EXE не требуется.
